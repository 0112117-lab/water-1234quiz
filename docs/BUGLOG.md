## FIXED — 이어풀기가 다음 장으로 넘어가지 않음
- **증상:** 예) 1과목 3장을 다 풀고 "이어풀기"를 눌러도 4장으로 가지 않고, 같은 3장 "다시 보기(1번부터)"만 떴다.
- **원인:** 홈의 이어풀기 카드가 `S.last.key`(마지막에 푼 장) 한 곳만 바라봄. 그 장이 완료 상태면 다음 장을 탐색하지 않고 재시작 버튼만 노출했다.
- **조치:** 마지막 장에 미응답이 남았으면 그 장을 이어서, **완료됐으면 목록 순서상 다음 미완료 장으로 자동 이동**하도록 로직 변경(뒤쪽에 없으면 앞쪽 탐색, 전부 완료면 다시 보기).
- **검증:** 수정 함수 구문·중괄호 균형 확인, 완료→다음장 이동 논리 점검. (실기기 스모크 테스트 권장)

## FIXED — 모바일에서 AI 버튼이 앱이 아닌 브라우저로 열림
- **증상:** "AI에게 질문하기"의 클로드/GPT 버튼이 설치된 앱이 아니라 웹으로 열림.
- **원인:** `window.open(https...)` 단일 방식이라 OS별 앱 연동 처리가 없었음.
- **조치:** `openAI`를 OS 분기 처리. Android는 `intent://`(앱 패키지 지정 + 웹 폴백), iOS는 유니버설 링크, PC는 새 탭.
- **검증:** 삼성인터넷에서 앱 직접 실행 확인(사용자 확인). **iOS는 아래 KNOWN ISSUE 참조.**

## FIXED — 배포 산출물이 라이브에 반영 안 됨(사용자 혼동)
- **증상:** 새 파일을 받아도 변경이 안 보임.
- **원인:** 다운로드한 **로컬 파일(`nt://...`)** 을 열어 테스트. GitHub에 커밋되지 않아 라이브(https)에는 옛 버전이 남아 있었음.
- **조치/가이드:** "GitHub 업로드 → https 라이브 URL 접속"을 표준 흐름으로 고정. 로컬 파일 테스트 지양.
- **상태:** 프로세스 가이드로 해결(코드 버그 아님).

## FIXED — 삼성인터넷 "현재 페이지 추가" 버튼 비활성(회색)
- **증상:** 홈 화면 추가 메뉴가 회색으로 눌리지 않음.
- **원인:** 로컬 파일 경로(`nt://media/external/...`)에서 접속. 브라우저가 로컬 경로의 홈 화면 추가/PWA 설치를 차단.
- **조치:** https 라이브 URL 접속 시 활성화됨을 안내. 더불어 `<head>`에 매니페스트/아이콘 추가 + 설정 화면에 "📲 홈 화면에 추가하기" 인앱 버튼(`addHome`) 신설.
- **검증:** https 접속 시 정상. 로컬 파일에서는 원래 불가(플랫폼 제약).

## KNOWN ISSUE (미해결 — 플랫폼 제약)

### iOS Safari에서 외부 앱(클로드/ChatGPT) 강제 실행 불가
- **증상:** 아이폰에서 AI 버튼이 앱이 아닌 웹으로 열림. 홈 화면 웹앱에서 특히 그러함.
- **원인:** Apple이 웹페이지/스탠드얼론 웹앱의 서드파티 앱 실행을 제한. 유니버설 링크가 인페이지 JS 이동에서 일관되게 발동하지 않음.
- **완화책:** 웹으로 열린 뒤 표시되는 "앱에서 열기" 배너 이용(기기·버전 따라 미표시). 앱 연동이 필요하면 Android(삼성인터넷/크롬) 사용.
- **분류:** 코드로 수정 불가한 플랫폼 한계. [확정]
